# m00 security review (pipeline stage 4, plans only)

Date: 27 Oct 2026. Scope: plans 00–09 under `docs/superpowers/plans/`, `CLAUDE.md`, `.gitignore`, `.env.example` and `docs/research/2026-10-27-technical-facts.md`. No code exists yet, so every finding is a plan defect. References are `plan:line`, where `01` means `2026-10-27-01-g0-renderer-quicklook.md`, and so on.

**Threat model:** a hostile Markdown/JSON/YAML/CSV/.env file opened in the app or in Quick Look; a hostile waitlist visitor; a network attacker on the Sparkle and Polar paths; a user bypassing licensing; the supply chain (npm, Sparkle, CI); and secrets leaking through logs, commits, CI or `.env`.

**Facts checked with WebFetch on 27 Oct:**
- Sparkle supports signed feeds: `SURequireSignedFeed` (2.9+) needs `SUVerifyUpdateBeforeExtraction` (2.7.3+). Our pin, 2.10.1, has both. (sparkle-project.org/documentation/customization/)
- Polar `validate` accepts `conditions` and `benefit_id` and returns 404 when "the conditions, benefit, or customer do not match". (polar.sh/docs/api-reference/customer-portal/license-keys/validate)

**Counts:** 0 P0, 4 P1, 25 P2.

There is no P0 because, as planned, a hostile file that gets script running still has no way out: the CSP sets `default-src 'none'` with no `connect-src`, every navigation is blocked, and there is no network `img-src`. The one exfiltration path found needs the user to export a PDF and send it on (#3).

**Two fixes reverse decisions the plans already pinned.** The user must approve both:
- #4 reverses 03:40 ("clock moved backwards → Pro").
- One of #3's options narrows plan 02's `../assets` image scope (02:819).

- **The Mermaid SVG path** (#8). `hostile.md` exercises only `click`.

## What's solid

- The CSP and nav guards are watched failing (01:994–1005). There are real positive controls: the beacon server (01:910–915) and the CSP-violation counter (01:932).
- `hostile.md` covers script, svg, iframe/object/embed, form, meta-refresh, base, link, `@import`, data-HTML, `javascript:` and `file:` links.
- `file:` survives only on `img[src]`, and only with the hook installed, with both directions tested (02:795–801).
- Mermaid runs with `securityLevel:'strict'`, loads lazily and has `suppressErrorRendering`.
- Licence benefit binding: a wrong product releases the activation, and a missing `benefit_id` fails closed (03:341–360). `refreshDoesNotResurrect` covers the deactivate race.
- The "404 never locks" invariant [F3d] is pinned by tests.
- `release_test.sh` guards, including no secret echo, are watched failing (03:829–856). The R2 upload uses a bucket-scoped token with exact-pinned wrangler (03:156, 03:908).
- Diagnostics carry no key and no paths (02:1296–1330). `TGForcePro` is compiled out of Release.
- The site `_headers` detach is watched failing (04:495). The tool page has `connect-src 'none'`.
- The waitlist function checks Origin, content type, a 2 KB cap and a honeypot, and logs no PII (08:486–500).
- App 2 masks `.env` values: the HTML never carries the values, and Quick Look never reveals them (06:420–425, 06:554–555).
- App 2 has a `__proto__` test and a YAML alias-bomb budget (06:261–285). The `tegelData` range is clamped.
- App 2's Quick Look has no `/` exception. Its `readonly-gate` is watched failing (06:833).
- KaTeX runs with `trust:false` and `maxExpand`, and hostile TeX tests caught the texmath `$` bug (07:253–266).
- User CSS goes in via `textContent`, with a watched-fail network guard (07:338–344). `verify-store-build` is watched failing (07:495). `smoke.yml` passes inputs through `env` (05:143).
- App 3 reads the selection only on the hotkey, and skips `AXSecureTextField`. Its dismiss monitor is mouse-only, with a test. `verify-no-keylogging.sh` is watched failing on a real event tap (07:859–878).
- Updates are signed with Sparkle EdDSA, notarised and use the hardened runtime. Sparkle is pinned to exactly 2.10.1.
